# Combined G02-G05 local candidate

The user reported regular GTAO looked good during a short session and requested
G02-G05 together for a combined acceptance pass. This is a local development
candidate on main, based on `5710aeb4626cc5f86ba0730b9afc3e1de5c4442d` plus M1.
The M1 package and stable v1.0.3 are preserved. Nothing is published.

## Scope and controls

| Feature | INI keys | Defaults | Restart / dependencies |
| --- | --- | --- | --- |
| G02 HQ GTAO | `graphics_gtao=1`, `graphics_ao_quality=1` | GTAO off; Regular quality | Restart; keep original SSAO enabled |
| G03 SSGI | `graphics_ssgi=1`, `graphics_gi_strength` | Off; strength 6, range 0-12 | Enable requires restart; strength is live |
| G04 Stochastic SSR | `graphics_modern_ssr=1`, `graphics_ssr_intensity` | Off; intensity 1, range 0-3 | Restart; keep original `effect_ssr=1` |
| G05 PCSS sun shadows | `graphics_pcss=1` | Off | Restart; replaces directional filtering after native shadow blur |

Both launchers and the native overlay expose these controls. The native HQ AO
checkbox selects Regular/HQ while the launcher uses a quality dropdown. The
existing restart footer tracks changed startup choices. Settings serialize through
the shared serializer and participate in custom presets. Immutable RTX 3070
presets, updater identities and NR settings remain unchanged.

## Source and integration

Primary pinned upstream: LanternEngine
`573f83fd366d70bf26ce788edb9775a1b863676a`, verified again on 11 November 2026.
HQ AO and SSR come from that revision. SSGI, PCSS and their matching shaders use
`4889a8a8bd72d74adc7ce49b89ddd951eba48bd2`: the later edit to those two systems
adds ray-traced scene capture, which is outside this batch. HQ AO origin is
`9244581284e2c5f315c9febb1f513a19dcc731b8` / PR #94.

- HQ AO uses the three-direction gather, a spatial denoiser and full internal-
  resolution compute AO over the game's bilateral upscale. The original packed-
  depth channels are preserved. Unsupported resource chains retain the existing
  upscale; initialization/VRAM guards disable the extra passes rather than forcing
  an unsupported allocation. AO strength is applied once through BloodborneX's
  existing game-constant hook, including the full-resolution pass.
- SSGI captures G-buffer albedo/normals and scene depth, gathers/denoises at half
  resolution and composites into the original scene before transparency or the
  NR/SR trigger. It owns separate history and retires resized images/views through
  the existing scheduler. No NR history or composition code is replaced.
- SSR replaces the matching reflection fragment shader, performs temporal resolve
  and optional full-resolution trace, and uses the upstream depth-aware composite
  only for the exact matching SPIR-V checksum. The water-offset patch also uses
  exact word/checksum guards. Other profiles retain original shader components.
  Original binaries remain in the disk cache; replacements are chosen at module
  creation for both cold and cached loads.
- PCSS records the original directional resolve inputs, follows the blur resource
  chain, and applies atlas-safe soft shadow filtering after native blur. G06 contact
  shadows are explicitly off. Cascade blending remains zero to avoid importing
  G09 guest hooks or changing the game's shadow matrices. No point shadows,
  volumetrics, ray tracing or resolution-control features are added.

All new effects default off and allocate GPU resources only when used. These
screen-space paths rely on the existing camera/upscaler tracking; without a valid
camera, layout or target, they retain the existing rendering path. Choosing Off
for the upscaler can disable camera-dependent effects; use DLAA, TAA or an upscaler
for acceptance. This port adapts the upstream recording-context API to the current
single recording thread instead of adopting the entire newer renderer.

## Rebuild source

Maintainable sources are `engine/tier1-lighting.patch` and its hash manifest,
applied **after** `tier1-gtao.patch` to a complete v1.0.3 NR source tree:

```powershell
python tools/apply-tier1-gtao.py C:\path\to\applied-v103-engine
python tools/apply-tier1-lighting.py C:\path\to\applied-v103-engine --check
python tools/apply-tier1-lighting.py C:\path\to\applied-v103-engine
```

Already-applied full engine sources in the candidate source ZIP need no patches.
Use the existing engine build and `tools/build-nr-release.ps1` packaging workflow.
The new candidate uses version `1.0.4-nr.rc2` and a separate local output root.

## Combined acceptance pass

Run the new candidate separately with a separate save folder. Configure your game
dump and, if desired, supply your NR runtime; no user settings/runtime are copied
from the M1 package. Enable original SSAO and SSR, enable GTAO, choose HQ, then
enable SSGI, stochastic SSR and PCSS before starting/restarting.

Check a sunlit courtyard, dark interior, reflective/wet ground and foliage. Start
with NR off to see each effect, then use your normal NR settings and multipass.
Check Balanced/Performance and DLAA/native inputs, scene transitions and menus.
If isolating an issue, disable one feature, restart and revisit the same scene.
Keep the log: initialization/module messages alone do not prove a visible effect.

GPU synthetic tests and compile checks are reported separately from this pending
gameplay acceptance. No FPS improvement or long-session certification is claimed.
