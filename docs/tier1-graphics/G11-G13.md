# G11-G13 final Tier 1 candidate

This development batch follows G01-G10 and preserves the v1.0.3 stable package
and earlier rc candidates. Source baseline is main
`5710aeb4626cc5f86ba0730b9afc3e1de5c4442d` plus the three earlier supplements.

## G11: point-light shadows

The coherent pre-RT Lantern implementation from
`4889a8a8bd72d74adc7ce49b89ddd951eba48bd2` supplies vk_point_shadow.cpp/.h and
point_shadow.comp. Latest Lantern main was rechecked as
`573f83fd366d70bf26ce788edb9775a1b863676a`; its replacement depends on RT and
newer draw-context/batching APIs. We retain the earlier matched descriptor ABI
instead of mixing its shader with the newer incompatible buffer layout.

This is screen-space ray marching on supported direct local-light draws,
not a ray-traced scene or new cubemap generator. Snapshot two packed HDR light
targets before the draw; after the draw, attenuate only their positive delta.
Existing accumulated light is retained. Match the known vertex shader, 1-12
light fragment families, two targets, buffer ranges and viewport/scissor.
Unknown families and indirect draws retain native lighting. Snapshot only after
the asynchronous pipeline skip decision; skipped draws cannot leave pending work.
Flush immediately after the same draw, before scene composition and NR/SR.

Use **Point-light shadows (restart required)** in launcher Graphics or the
in-game graphics overlay. Default is off (`graphics_point_shadows=0`). Strength
is live in the overlay, 0..1, default .85 (`graphics_point_shadow_strength`).
Both keys persist, participate in selective custom presets and the existing
restart indicator. The immutable RTX 3070 profiles remain unchanged.

Resources and the compute pipeline are created lazily on the first supported
draw. Disabled/zero-strength shadows make no GPU allocations or snapshot copies.
Reduced scene targets use the existing SceneTargets proxies and internal size.
Storage-format/feature/budget guards retain native lighting when unsupported.
Snapshots and temporary views retire after GPU completion; target UIDs protect
against reuse. Transfer/compute/attachment transitions surround each draw.
The shader is compiled through existing host shaders; it does not replace or
serialize game SPIR-V, and no cache identity/schema changes are required.

Screen-space limitations include missing off-screen occluders, short ray reach,
distance fade and light-edge noise. Enabling this augments existing lighting;
it does not force the game's original dynamic-shadow switch on or replace
native shadow maps. Additional per-light copies and compute have a GPU cost.

## G12: conservative occlusion

Keep the existing query ring, asynchronous resolution, guest-memory ownership
checks, predication safeguards and five-result visibility history. Adapt the
current upstream conservative visibility policy to this older counter model:

- Age queries in displayed-frame numbers rather than submission counts.
- Only fresh, complete, nonempty, all-zero intervals may report occluded.
- Unavailable, incomplete, stale or positive intervals report plainly visible,
  including precise queries with small counts (avoids nearly hidden light proxies).
- Union sample results instead of summing, preventing overflow to false zero.
- Reject frame-counter reversals and bound late writes to previously owned
  answers using subtraction rather than overflow-prone doubled limits.

This favors visible geometry over aggressive culling. It deliberately changes
positive-count interpretation; check lamp/glare behavior and performance in game.
`BB_OCCLUSION=0` remains the existing always-visible diagnostic fallback.

## G13: bounded output-preserving optimization

Port the upstream conditional camera-inverse calculation: compute the affine
inverse and its diagnostic gap only when the computed-inverse toggle or camera
logging consumes them. Keep the exact same inverse function, toggle expression,
game matrix selection and log values. No NR math or frame-history rewrite.

Already-present async pipeline compilation, texture/buffer memoization, image
hash reuse and completion-based FG retirement are retained, not merged again.
This completes the reviewed Tier 1 optimization scope; it does not assert that
all future upstream optimizations are incorporated or promise an FPS gain.

## Rebuild and acceptance

Apply `tools/apply-tier1-final-renderer.py <engine-source>` after GTAO, lighting
and atmosphere/shadows supplements. Full source packages already contain all
changes; do not reapply historical patches. Use existing build.sh or release
helpers. See G11-G13-VALIDATION.md for executed checks and candidate path.

1. Compare point shadows off/on after restart in a fixed scene with lamps, walls,
   ground and moving characters. Adjust strength 0/.5/1; watch for unrelated
   lighting dimming and record the Point shadows activation log.
2. Repeat DLAA, DLSS SR Balanced/Performance, NR off/single/multipass and FSR.
   Test reduced resolution, area transitions, menus and repeated restarts.
3. Test lamps/glare at occluder edges with G12 and its diagnostic fallback;
   look for missing geometry, overly dark proxies and performance changes.
4. Combine all Tier 1 effects, then FG/HDR where supported; watch VRAM and run
   a longer session. Compile/GPU fixtures do not replace this gameplay test.
